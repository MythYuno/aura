# AURA 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ricostruire AURA come web app che risponde a tre domande — quanto posso spendere oggi, posso permettermi questa cosa, dove sono finiti i soldi — su un ciclo che parte dal giorno dello stipendio.

**Architecture:** Il motore è un insieme di funzioni pure in `src/cycle/` (confini, budget, sforamento, riconciliazione), coperte da `node:test`. Sopra, un hook di stato unico su `localStorage` e tre schermate che non contengono calcoli. Le primitive UI replicano le superfici di sistema iOS: nessun componente calcola, nessuna funzione disegna.

**Tech Stack:** React 18, Vite 5, Tailwind 3, `@phosphor-icons/react`, `node:test` + `node:assert`. Nessuna dipendenza nuova.

**Spec:** [docs/superpowers/specs/2026-10-28-aura-redesign-design.md](../specs/2026-10-28-aura-redesign-design.md)

## Global Constraints

- Solo web app, PWA installabile. Niente Capacitor, niente build nativa.
- Nessun server, nessun account, nessuna analytics. Dati solo in `localStorage`.
- Nessuna migrazione: nessuna compatibilità con lo storage v0.8. Si riparte vuoti.
- Giorno stipendio: default **16**, configurabile.
- Confini del ciclo dal giorno configurato, **non** dalla data di accredito reale.
- Se il giorno non esiste nel mese, si usa l'ultimo giorno del mese.
- Ogni movimento è **o libero o vincolato** (fisso / accantonamento / obiettivo): campo obbligatorio, solo i liberi entrano in `P`.
- Stato: `ritmo ≥ 0,8` verde · `0,4 – 0,8` ambra · `< 0,4` oppure `R ≤ 0` rosso.
- Colore semantico **solo sulla barra**. La cifra porta l'accento grafite. Verde, ambra e rosso non si usano altrove.
- Superfici — chiaro: fondo `#F2F2F7`, carte `#FFFFFF`, raggio `11`. Scuro: fondo `#000000`, carte `#1C1C1E`.
- Accento: `#1C1C1E` in chiaro, `#F2F2F7` in scuro. Nessuna tinta di marca satura.
- Tipi di sistema (`-apple-system`), nessun font importato. Large Title 34/41, Body 17/22, Subhead 15, Footnote 13.
- Cifra del giorno in Title 1, **28 pt**. Mai un numero gigante.
- Quadratino categoria **29 pt**, raggio **7**, glifo Phosphor bianco peso `fill`. Icone non-categoria: peso `regular`.
- Tab bar Liquid Glass iOS 27: sfocatura, **bordo definito**, nessuna ombra portata, highlight interno in alto. Scroll edge "duro" con linea inferiore.
- La modalità segue il telefono: nessuna impostazione.
- Rispetta `prefers-reduced-transparency` e `prefers-contrast`.
- Nessun file supera le **300 righe**. Totale sotto le **5.000**.

## Review Focus

Classi di input che la spec implica senza dedicarvi un requisito, in ordine di quanto farebbero male. Ognuna ha il suo test nel task che possiede il codice.

1. **Ultimo giorno del ciclo: `D = 1`, e il giorno dopo `D` passa a quello nuovo.** Un `R / D` con `D = 0` produce `Infinity` sulla schermata principale. → Task 2 e 3.
2. **`L ≤ 0`**, quando fisse più obiettivo pareggiano o superano lo stipendio: il `ritmo` ha `L` al denominatore. → Task 3.
3. **Giorno stipendio 29, 30 o 31 in febbraio**, e negli anni bisestili. → Task 2.
4. **Importo digitato con virgola, punto, separatore di migliaia, segno meno o venti cifre** nel campo Posso?. → Task 4 e 10.
5. **`localStorage` assente o pieno** (navigazione privata, quota esaurita): l'app deve partire e restare usabile in sola lettura. → Task 6.
